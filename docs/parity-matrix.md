# Codex Desktop parity matrix

codexRS is a native Rust replacement for Codex Desktop. The release target is
behavioral and UX parity without Electron, Tauri, Wry, WebView, Node.js, or a
browser runtime.

This matrix is the contributor-facing source of truth. A row is complete only
when the visible behavior works through the official app-server or a native
platform boundary, has focused regression coverage, and has been compared with
the reference UI at the same state and viewport.

## Reference baseline

| Source | Pinned reference |
| --- | --- |
| Windows package | `OpenAI.Codex 26.721.3996.0 x64` |
| Desktop bundle | build `5828`, internal version `26.721.31836` |
| Bundled Codex CLI | `0.146.0-alpha.3.1` |
| CLI SHA-256 | `39e9e041ea33ac34aad9578adfe660c5c7a6dc8f82620b77623960f9352a6ef3` |
| Stable app-server schema | 89 client request methods |
| Experimental schema | 126 client request methods |
| UI inspection date | 2026-07-25 |

Evidence comes from:

- the official OpenAI feature documentation and product demo;
- a read-only inspection of the locally installed `app.asar`;
- schemas generated by the pinned official `codex app-server`;
- focused probes through an official supervised app-server process;
- the current codexRS source and native UI.

Extracted upstream code and assets are research material only. They stay under
ignored `target/` paths and are never redistributed or committed.

Status values:

- `done`: usable end to end and covered by the relevant release gates;
- `partial`: a real vertical slice exists, but the reference exposes more;
- `missing`: no usable end-to-end implementation yet;
- `platform`: implemented on only part of the supported platform matrix.

The stable renderer contains `foregroundClicks`,
`foregroundAndBackgroundClicks`, and `off`, but the inspected stable main
process reads and writes that mode through macOS `/usr/bin/defaults` only.
Windows returns no mode and the setter is a no-op, so click sound is not a
Windows/Linux parity gap.

The inspected stable main process opens the primary window at `1280×820`,
enforces a `480×600` minimum, persists normal bounds plus maximized state under
`electron-main-window-bounds`, clamps undersized saved values, and restores
only placements intersecting a current display work area.

The stable renderer uses a 275 px sidebar, closes competing right-side panels
at 960 px or below, and closes the adaptive sidebar at 720 px or below. Explicit
sidebar toggles suspend that automatic behavior, while right-side panels are
restored after the viewport widens again.

Its shared dialog surface caps width at 92% of the viewport. Tall stable
dialogs additionally reserve a 16 px inset on every side and scroll their
content instead of escaping the window.

The stable Windows shell uses a 34 px client-decorated title bar with the
sidebar, Back, Forward, File, Edit, View, and Help controls followed by 46 px
native minimize/maximize/close hit areas. Its menu contract and accelerators
were recovered from the packaged stable main/renderer bundles without
modifying or extracting the installed app.
